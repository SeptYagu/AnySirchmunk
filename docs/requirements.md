# AnySirchmunk 需求说明

## 1. 背景

Sirchmunk 可以围绕本地资料进行查询规划、证据分析、答案生成和知识积累，但在大型 Windows 文献目录中使用 `ripgrep-all` 临时解析文件时，检索速度、覆盖率和候选文件质量不够稳定。

AnyTXT Searcher 已经为本地文件建立全文索引，能够快速返回相关文件和文本片段，但它本身不提供 Sirchmunk 式的 AI 分析、证据组织、知识聚类和历史知识复用。

本项目需要组合两者，而不是重新实现完整的搜索引擎或知识系统。

## 2. 产品目标

用户在 Sirchmunk 中提出问题后，Sirchmunk 继续负责理解问题和生成检索词；关键词搜索改由 AnyTXT 完成。AnyTXT 返回的文件路径和片段进入 Sirchmunk 原有证据链，最终答案和知识记录仍由 Sirchmunk 生成与保存。

预期流程如下：

1. 用户直接提出问题；未限定范围时自动发现本机固定盘中的 AnyTXT 索引，或由 `ANYTXT_GLOBAL_ROOTS` 显式覆盖，也可以明确限定一个或多个目录。
2. Sirchmunk 生成关键词或在 ReAct 循环中提出新的关键词。
3. AnyTXT 在现有索引中查找候选文件并返回命中片段。
4. 集成层校验路径，应用目录、深度、扩展名和排除规则。
5. Sirchmunk 从候选文件读取所需内容，生成带来源的答案。
6. Sirchmunk 将值得复用的结果写入现有 `KnowledgeStorage`。
7. 后续问题可以复用已经保存的知识簇。

## 3. 功能需求

### FR-1：AnyTXT 连接

- 通过可配置 URL 连接 AnyTXT 本地 JSON-RPC 服务。
- 接口固定为已在 AnyTXT **Windows X86_64 OCR 1.3.3514** 上验证的 v1 API（`anytxt.v1.*`），默认地址 `http://127.0.0.1:9924/rpc`。
  旧版 9920 的 `ATRpcServer.Searcher.V1.*` 接口不受支持：它无法支撑一次完整的长查询，且使用另一套参数信封。
- 为每次请求设置超时。
- 对连接失败、超时、非法响应和接口错误给出可诊断日志。
- 不把本地 API 暴露到公网，也不要求 AnyTXT 账号或云服务。

### FR-2：内容检索

- 支持单个关键词和多个关键词。
- 支持显式根目录和“未指定范围”检索。后者默认枚举 Windows 固定盘并以只读 RPC 探针确认哪些盘已入 AnyTXT 索引；`ANYTXT_GLOBAL_ROOTS` 非空时覆盖自动发现。不得遍历文件、修改索引，也不得把空 `filterDir` 当作全局范围。
- 支持用户在需要时限定一个或多个搜索根目录。
- 调用 `anytxt.v1.getResult` 获取候选文件，调用 `anytxt.v1.search` 获取精确命中总数，调用 `anytxt.v1.getFragment` 获取匹配片段；多词字面短语可调用 `anytxt.v1.getText` 验证索引文本中的精确子串，但最终证据仍从原文件读取。参数直接位于 `params`。
- 保留 AnyTXT 返回的稳定文件标识、绝对路径、修改时间和文件大小等可用元数据。
- 去除重复文件，并限制请求数、文件数和片段总字符数。
- 片段请求使用独立于候选发现的请求预算；任一预算耗尽只把结果标记为不完整并保留已发现的候选，不得丢弃候选或向调用方抛出预算异常。
- 区分页大小与总候选预算；验证分页语义后继续获取结果，后置过滤不得把第一页无有效记录视为全局零结果。
- 返回内部完整性状态及原因。AND/NOT 仅在确认上游为文件级语义且相关集合完整时执行；不完整时按范围回退或明确报告无法准确执行。
- 字面量、正则、大小写和计数单位必须与固定上游版本等价。不能用片段未命中证明原文未命中，不能将正则降级为普通词；未知能力按范围回退或报不支持。

### FR-3：Sirchmunk 兼容

- 输出 Sirchmunk 当前检索链可以消费的 `begin`、`match`、`end` 事件。
- 每个 `match` 至少包含 `data.path.text` 和 `data.lines.text`。
- 将检索后端标记为 `anytxt`，供 telemetry 和问题排查使用。
- 现有 `KeywordSearchTool`、FAST 候选排序和 DEEP ReAct 工具无需理解 AnyTXT 的 RPC 格式。

### FR-4：范围与过滤

- 未指定范围时允许返回 AnyTXT 全局索引中的文件。
- 用户明确指定搜索根目录时，结果必须位于这些目录中。
- 路径比较应适配 Windows 大小写不敏感和路径分隔符。
- 支持 Sirchmunk 的 `include`、`exclude` 和 `max_depth` 参数；AnyTXT 无法原生表达的规则由适配层进行结果过滤。
- 不读取搜索范围外的文件。
- 全局与显式范围须在入口区分，并贯穿 FAST、DEEP、ReAct、文件读取与知识复用；显式范围的真实路径校验覆盖目录联接，不仅做字符串前缀判断。

### FR-5：回退策略

- 提供 `rga`、`anytxt` 和后续可选的 `auto` 后端模式。
- 第一版中，`anytxt` 请求失败时可以按配置回退到 `rga`。
- 空搜索结果和后端故障必须区分；正常的零结果不应被误报为故障。
- 日志和检索 metadata 应记录实际后端及回退原因。
- 显式目录查询只在原范围回退；全局查询仅在配置 `ANYTXT_FALLBACK_ROOTS` 时回退，并标明范围已缩小。未配置时报告后端不可用或查询无法执行，不扫描当前目录或所有磁盘。
- 需要精确语义但结果不完整时，也可按上述范围回退。每次检索最多回退一次；取消和总预算耗尽不得启动回退。

### FR-5A：版本能力探测

- 启动时或首次请求时验证 AnyTXT RPC 是否可用。
- 未显式指定范围时，优先使用 `ANYTXT_GLOBAL_ROOTS`；否则默认枚举固定盘，以不可能命中的只读计数探针区分已索引盘（`errno=0`）和未索引盘，再逐根查询、去重并缓存发现结果。关闭自动发现且没有显式根时，空 `filterDir` 的结果必须标记为不完整。
- 接口基线采用已验证的 Windows X86_64 OCR 1.3.3514 v1 配置；未知版本或模式不得凭普通查询的零结果切换参数。
- 目录、分页、字面量和正则分别记录 verified/unsupported/unknown。只有已知内容且确认已入索引的非私人测试文件及正反例才能证明语义；无测试文件时保持未知。
- 健康检查仅验证连接和结构，不自动写文件或改索引；模拟 RPC 测试不能代替真实能力验证。实例重启或版本/模式变化后使相关能力缓存失效。
- 不假定图形界面的搜索模式一定等价于 JSON-RPC 的模式。
- 记录检测到的 AnyTXT 版本、RPC 方法和能力，不记录用户文件名或文档内容。

### FR-6：文件名搜索

- 第一阶段的 `FILENAME_ONLY` 模式继续使用 Sirchmunk 原有文件枚举方式。
- 在确认当前 AnyTXT 版本存在稳定的文件名检索接口后，再评估替换该路径。
- 内容检索接入不应降低文件名搜索能力。
- `anytxt` 模式的文件名枚举遵循 FR-5 的目录契约；全局且无回退根目录时，FILENAME_ONLY 报告 scope_required，可选 FAST 文件名步骤跳过并记录原因。此枚举不受故障回退开关控制；默认 `rga` 模式行为保持不变。

### FR-7：知识持久化

- 继续使用 Sirchmunk 的 `KnowledgeStorage`、`KnowledgeCluster` 和 `EvidenceUnit`。
- 不迁移或改写现有 Parquet schema。
- 知识记录中的来源路径必须保持为原始文件的绝对路径。
- 更换检索后端后，知识复用、合并、演化和证据追踪仍应工作。

### FR-8：配置

计划增加以下环境变量：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `SIRCHMUNK_SEARCH_BACKEND` | `rga` | 选择检索后端 |
| `ANYTXT_API_URL` | `http://127.0.0.1:9924/rpc` | AnyTXT v1 本地服务地址，必须是 loopback HTTP |
| `ANYTXT_SEARCH_LIMIT` | `300` | RPC 页大小，取值范围 1–300（v1 越界会返回 `-32602`，故在配置阶段即校验），不能代替总候选预算 |
| `ANYTXT_REQUEST_TIMEOUT` | `15` | 单次 RPC 超时秒数，受剩余总预算限制；超时后重试一次 |
| `ANYTXT_FALLBACK_TO_RGA` | `true` | 内容检索故障、不支持或不完整时是否允许有界回退 |
| `ANYTXT_FALLBACK_ROOTS` | `[]` | 全局模式回退/文件名枚举的绝对目录 JSON 数组；不改变 AnyTXT 全局检索范围 |
| `ANYTXT_TOTAL_TIMEOUT` | `30` | 每次 retrieve 总预算秒数；与调用方 timeout 取较小值 |
| `ANYTXT_MAX_CONCURRENCY` | `2` | 同类 RPC 请求的最大并发数；`getResult` 与 `getFragment` 之间强制互斥，因为 1.3.2477 在两类请求重叠时会退出服务（实测见 anytxt-capabilities.md 4.4） |
| `ANYTXT_PAGE_ORDER` | `3` | 分页排序；3 = 路径升序。默认排序不保证跨页稳定，会导致长枚举漏页或重复 |
| `ANYTXT_EXACT_COUNT` | `true` | 是否先用 `anytxt.v1.search` 取精确命中总数；开启后完整性由"已收到的行数是否等于总数"判定，关闭则退回分页启发式 |
| `ANYTXT_AUTO_DISCOVER_ROOTS` | `true` | 未指定范围且没有显式全局根时，是否只读探测本机固定盘的 AnyTXT 索引；不扫描文件、不修改索引 |
| `ANYTXT_GLOBAL_ROOTS` | `[]` | 全局检索根目录 JSON 数组；非空时覆盖自动发现，适合固定部署范围 |
| `ANYTXT_MAX_REQUESTS` | `100` | 每次 retrieve 的总 RPC 请求数（含就绪检查与精确计数） |
| `ANYTXT_MAX_CANDIDATES` | `3000` | 每次 retrieve 的去重候选文件上限 |
| `ANYTXT_MAX_FRAGMENT_CHARS` | `100000` | 每次 retrieve 的片段总字符上限 |
| `ANYTXT_MAX_FRAGMENT_REQUESTS` | `100` | 每次 retrieve 的片段请求上限；片段预算独立于候选发现，避免大量片段请求饿死分页 |

`ANYTXT_API_MODE` 已随 legacy 接口一起移除。若环境或 `.env` 中仍存在该变量且值不是 `v1`，
配置解析直接报错——静默改用另一套接口属于禁止的语义漂移。

配置值不得硬编码到检索逻辑中，也不得保存密钥或用户私有路径到仓库。

数字预算必须为正值；回退根目录必须为有效绝对目录，非法配置报错，不静默采用其他范围。以上为第一版初始预算，性能基准后如需调整，应记录依据。多关键词、多目录、能力探测、分页、片段与回退共享总预算。

## 4. 非功能需求

### 兼容性

- 保持 Sirchmunk 的公开搜索调用、API 请求和 MCP payload 兼容。
- 未配置 AnyTXT 时保持原有默认行为。
- 以 AnyTXT Windows X86_64 OCR 1.3.3514 的 v1 API 为已验证接口基线。仅使用 `getText` 做多词字面短语的候选验证与片段展示，不把它当作最终证据；不依赖 `getFragmentAll`、`ocr`、`syncIndex` 或 MCP。
- 对 AnyTXT Beta API 的目录通配符、正则模式和版本差异进行能力探测。
- 已锁定 Sirchmunk 完整 commit SHA、Python/依赖版本和许可证，采用固定版本补丁集交付，附干净安装、测试与回滚步骤；锁定信息见 [baseline.json](../baseline.json)。
- 验证全局/显式范围与 FAST、DEEP 初始检索、ReAct、文件名搜索、知识复用的组合，不能仅以事件结构相同认定兼容。

### 性能

- AnyTXT 内容检索不重新遍历整个文献目录或建立第二套索引；显式范围内的 rga 回退和文件名枚举属于例外，必须计入耗时与预算。
- 多关键词请求应有并发上限，避免阻塞 AnyTXT 服务。
- 同一文件与相同 pattern 的片段请求应去重，不能丢掉其他关键词的片段。
- 在进入 LLM 之前限制候选文件和片段文本规模。
- 固定语料上对比相同范围和 K 的候选 recall@K、检索 P50/P95、请求数、片段字符数与回退率；LLM 总时延单列。基准方法和暂定门槛见技术方案第 6 节。

### 可靠性

- AnyTXT 崩溃或尚未启动时，Sirchmunk 进程不应崩溃。
- 单条记录缺失字段或文件不存在时，跳过问题记录并标明结果不完整；无效 JSON 属于请求失败，不能伪装成正常零结果。此前有效候选可保留，但精确运算必须拒绝不完整输入。
- 取消 Sirchmunk 查询时，应尽快取消尚未开始的 AnyTXT 请求。
- 预算耗尽、重复页和索引变化必须停止或标记不完整；单次 RPC 超时不应使总耗时无限累计。

### 可观测性

- 记录请求耗时、候选数、有效文件数、片段请求数、实际后端和回退状态。
- 内部 metadata 保留 complete、truncated、reason、actual_backend、effective_scope，以及回退缩小范围时的 scope_reduced；不得在工具合并中丢失。保持现有公开 payload 兼容。
- 日志不得包含 LLM 密钥或整份私人文档内容。

## 5. 数据与多设备使用

文献路径在多台设备上都为同一绝对路径，例如 `D:\OneDrive\...`，可以提高知识记录跨设备复用的成功率。Sirchmunk 工作目录也可以放入 `D:\OneDrive\SirchmunkData`。

第一阶段的约束：

- OneDrive 只负责文件同步，不提供数据库并发控制。
- 两台设备不得同时修改同一个 `knowledge_clusters.parquet`。
- 启动 Sirchmunk 前应等待同步完成；结束搜索后也应等待知识文件上传完成。
- AnyTXT 的索引由每台设备分别建立，不直接通过 OneDrive 共用。
- 若以后需要并发写入，应把知识存储升级为带事务和同步协议的服务端存储。

## 6. 验收标准

1. 使用一个能在 AnyTXT 中命中的关键词执行 FAST 搜索，日志显示 `anytxt`，答案包含真实文件来源。
2. DEEP 模式在初始检索和 ReAct 后续检索中都能发现 AnyTXT 返回的文件。
3. 查询完成后，知识簇仍写入原有 Parquet 文件，并可在下一次查询中复用。
4. 停止 AnyTXT 服务后，显式目录内按配置回退；全局有配置根目录时仅回退到该范围并标记范围缩小，无配置根目录时明确报告不可用。
5. 将搜索路径限定到一个子目录时，不返回其他目录中的同名或同内容文件。
6. 中文、英文、带空格及 `a.b`、`C++`、括号、反斜杠和大小写正反例符合已声明语义；未知能力明确回退或拒绝，不能静默改变匹配含义。
7. 未启用 AnyTXT 时，现有 Sirchmunk 行为和配置保持不变。
8. 未指定路径时优先按 `ANYTXT_GLOBAL_ROOTS`，否则自动发现已索引固定盘并逐根合并；显式指定路径时只返回该范围内的文件。关闭自动发现且未配置根时，结果明确标记为不完整。
9. 在本机 1.3.2477 中不使用空 `filterDir` 冒充全局搜索，也不依赖无效的 `"*"` 写法；空 `filterDir` 的降级行为有测试覆盖并带告警。
10. 超过 300 条的交集和排除项、第一页全被过滤、重复页及部分失败均符合完整性契约；不完整结果不得产生伪精确 AND/NOT/计数。
11. 验证完整的范围/调用模式矩阵，包括无路径 DEEP/ReAct，以及全局无目录时文件名搜索的明确处理。
12. 无测试语料时语义能力保持 unknown；健康检查成功和普通查询零结果均不能改变该状态。
13. 取消、总预算耗尽后不发起新请求或回退，实际请求数、候选数、片段字符数符合配置上限。
14. 使用至少 30 个固定查询完成冷/热基准；共同支持查询集上的平均 recall@K 不低于 rga，热缓存检索 P95 不高于 rga 的 80%，精确语义测试全部通过。提交实际结果，不将设计目标写作已验证结论。

## 7. 暂不包含

- 替代 AnyTXT 的索引创建、更新或文件监控功能。
- 修改 Sirchmunk 的知识数据模型或迁移现有知识文件。
- 多设备同时写入同一知识库。
- 通过公网访问 AnyTXT。
- 第一阶段重新设计 Sirchmunk Web 界面。
- 把 embedding 改为云端服务；这属于独立的后续功能。

## 8. 已验证的 AnyTXT 基线

截至 2026-09-16，本机安装版本为 **Windows X86_64 OCR 1.3.3514**（此前为 1.3.2477，其长查询会退出服务，已不再支持）。官网当前 Windows X86_64 普通版为 1.3.3541、OCR 版为 1.3.3514；二者是不同安装包，不能用普通版版本号要求 OCR 版升级。
接口基线为 v1：`http://127.0.0.1:9924/rpc`。已确认：

- v1 方法的 JSON-RPC 2.0 信封为 `{"result": {"errno": 0, "data": {"input": {...}, "output": {...}}}}`，
  参数**直接位于 `params`**；请求必须同时带 `Accept: application/json` 与
  `Content-Type: application/json`，缺少任一头部返回 `HTTP 400`。
- `anytxt.v1.getResult` 返回 `field`、`count` 与 `files`（字段 `fid`、`lastModify`、`size`、`file`），
  其中 `count` 是**本页行数**，不是命中总数。
- `anytxt.v1.search` 返回**精确命中总数**，且受 `filterExt` 约束（同一目录同一关键词：`*` 为 77，
  `*.pdf` 为 64，`pdf;docx` 为 65），因此可以按相同过滤条件给出权威总数。
- `anytxt.v1.getFragment` 返回 `output.text`，命中词被 `*<<*`/`*>>*` 包裹；该标记属于展示层，
  不得进入证据。
- `anytxt.v1.status` 返回 `output.return`（引擎是否加载完成），可用于真正的就绪检查。
- `result.errno` 是业务状态而非传输错误：`filterDir` 指向未索引卷、`fid` 无法解析时都返回
  `errno = 1` 与空载荷，而参数错误走 JSON-RPC `error`（缺参、`limit` 越界、`order` 越界、
  空 `pattern`、负 `fid` 均为 `-32602`）。忽略 `errno` 会让"目录不可检索"与"目录内无命中"不可区分。
- 空 `filterDir` 仍被服务端解析为它自己的当前目录（1.3.2477 与 Windows X86_64 OCR 1.3.3514 均为 `C:`），只返回该卷结果，
  **不是**全局搜索；`filterDir="*"` 返回零结果。
- 逐卷根目录（`"C:\\"`、`"D:\\"`、`"E:\\"`）可以分别检索；`"C:,D:,E:"` 形式返回零结果。
- 没有直接枚举已索引卷的方法；当前实现枚举固定盘后以只读 `anytxt.v1.search` 探针判断索引可用性，显式 `ANYTXT_GLOBAL_ROOTS` 仍可覆盖。
- 已移除的 9920 接口（`ATRpcServer.Searcher.V1.*`，参数嵌在 `params.input`）在 Windows X86_64 OCR 1.3.3514 上仍可响应
  单次请求，但在真实 DEEP 负载下会让服务重启，故不再支持。
- 参数约束：`limit` ∈ [1, 300]、请求体上限 1 MiB、非 loopback 的 Host/Origin 返回 `403`。

索引规模等环境数据、官方版本差异与证据来源见 [anytxt-capabilities.md](anytxt-capabilities.md)。
